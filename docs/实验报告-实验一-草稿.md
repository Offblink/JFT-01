## 二、实验目标

1. 独立完成 MyBatis 开发环境的搭建与调试（Maven + Git + 数据库）；

### 3.4 功能实现与测试

`UserMapper` 接口 + XML 映射实现：`findAll`、`findById`、`findByUsernameLike`（`LIKE CONCAT('%', #{keyword}, '%')` 预编译防注入）、`addUser`（`useGeneratedKeys` 自增主键回填）、`updateUser`、`deleteUser`。

测试类 `UserMapperTest`：
- `@Before` 统一构建 `SqlSessionFactory`，各测试复用；
- `testCrudLifecycle` 以插入回填的自增 id 贯穿"增→改→查→删"，消除对固定 id 的顺序依赖，末尾 commit 并清理数据；

## 五、问题与解决方案（典型问题 2 个）

**问题 1：编译报 `java.lang.ExceptionInInitializerError ... TypeTag :: UNKNOWN`**
- 现象：IDEA 构建即失败。
- 定位：该异常为旧版 Lombok 注解处理器在新 JDK 上初始化崩溃的已知症状；本项目实体类手写 getter/setter，Lombok 纯属多余依赖。
- 解决：从 pom.xml 移除 lombok 依赖，`mvn clean compile` 验证通过。

**问题 2：运行测试报 `ClassCircularityError: java/lang/Module$ReflectionData`**
- 现象：JUnit 启动即崩，退出码 1；运行命令第一行显示使用的是 jdk-24 的 java.exe。
- 定位：JDK 24 与 IDEA 测试启动器的 javaagent 不兼容，且偏离课程 JDK 基线。
- 解决：将运行 JDK 调整为老师推荐的 JDK 21 后恢复正常。

**（备选问题 3：控制台中文乱码**——Windows 控制台 GBK 与 UTF-8 输出不一致，数据无误；IDEA 内设置 UTF-8 解决。）

## 六、实验总结与思考

**收获**：完成从环境搭建到 CRUD 全链路；建立了"配置文件路径强契约"（namespace/资源路径/方法名一一对应）的调试心智；学会用 SQL 日志（Preparing/Parameters/Total）核对每条语句的真实形态。

**思考题解答**：

1. **#{} 与 ${} 的区别**：`#{}` 生成 PreparedStatement 占位符 `?`，参数预编译绑定，防 SQL 注入；`${}` 直接字符串拼接进 SQL，仅在动态表名/排序字段等无法参数化的场景使用且必须校验输入，禁止用于接收用户输入（如 `' OR '1'='1` 可直接注入）。
2. **三大核心组件关系与生命周期**：`SqlSessionFactory` 由配置构建，应用级单例，重量级；`SqlSession` 由工厂开启，请求/方法级，非线程安全，用完必须 close；Mapper 接口无实现类，由 MyBatis 动态代理生成，代理对象绑定到 session，执行时将方法调用翻译为映射的 SQL。
3. **N+1 问题**：查 1 次主列表后对每条记录再各查 1 次关联数据（共 N+1 次）。例：查询 10 个员工后再按 dept 逐条查部门信息。优化：JOIN 一次查出，或批量 IN 查询后在内存组装。
4. **手写 XML vs 条件构造器**：XML 适合复杂 SQL（多表 JOIN、复杂动态 SQL、DBA 可审核）；MP 条件构造器适合单表动态条件（防字段名写错、开发快）。本节为多表能力打基础，第 2 章引入 MP 后对比。
5. **AI 代码质量问题与校验手段**：常见问题包括依赖超配、引用不存在的方法、硬编码测试数据（顺序依赖）、字段与表结构不符。校验手段：编译验证、真实运行、逐条对照表结构、审计测试独立性。
