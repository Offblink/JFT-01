# 实验一 · 日志排查演练记录（指导书任务 5.1）

> 按指导书要求故意制造三类错误，观察日志现象、定位原因并修复。
> 每项演练后已恢复正确代码，全部测试回归通过（21/21）。

## 演练 1：占位符大小写错误（#{empName} → #{empname}）

**篡改点**：`EmpMapper.xml` 的 insertEmp 语句 VALUES 里 `#{empName}` 改为 `#{empname}`。

**日志/报错现象**：

```
org.apache.ibatis.exceptions.PersistenceException:
### Error updating database.  Cause: org.apache.ibatis.reflection.ReflectionException:
There is no getter for property named 'empname' in 'class com.offblink.entity.Emp'
```

**原因分析**：`#{}` 里的名字是实体属性名，MyBatis 通过反射调 `getEmpname()` 取值；实体只有 `getEmpName()`，属性名大小写敏感，取不到就抛 ReflectionException。

**解决**：占位符必须与实体属性名逐字符一致；编译期查不出（XML 是字符串），靠运行日志第一时间定位。

## 演练 2：resultMap 列名写错（column="emp_name" → column="emp_nam"）

**篡改点**：resultMap 中 `<result property="empName" column="emp_name"/>` 的列名改为 `emp_nam`。

**日志/现象**：

```
Emp{empId=1, empName='null', gender='男', dept='研发部', ...}
Emp{empId=2, empName='null', ...}   ← 4 行全部 empName 为 null
java.lang.AssertionError  ← assertNotNull(list.get(0).getEmpName()) 失败
```

**原因分析**：**静默失败**——不存在的列映射被直接跳过，不抛任何异常，只有字段悄悄为 null。SQL 正常执行（日志里 `<== Columns:` 照常输出），这是结果映射问题里最难发现的一类。

**解决**：写 resultMap 后必须跑一条查询核对每个字段；断言关键字段非空能第一时间暴露此类问题。

## 演练 3：删除 useGeneratedKeys 主键回填

**篡改点**：insertEmp 标签去掉 `useGeneratedKeys="true" keyProperty="empId"`。

**日志/现象**：

```
DEBUG c.o.mapper.EmpMapper.insertEmp - <==    Updates: 1     ← 插入本身成功
新增影响行数：1，回填主键 empId = null                        ← 对象上的 id 是 null
java.lang.AssertionError                                     ← assertNotNull(emp.getEmpId()) 失败
```

**原因分析**：INSERT 正常执行、数据库自增主键照常生成，但 MyBatis 不知道要把生成值写回入参对象——后续"改/查/删"拿不到 id，链路断裂。与演练 2 同属静默失败。

**解决**：需要回填就必须同时声明 `useGeneratedKeys="true"`（开关）和 `keyProperty="empId"`（写回哪个属性）；注解方式等价物是 `@Options(useGeneratedKeys = true, keyProperty = "id")`。

## 演练结论

三类错误对应参数绑定、结果映射、主键回填三个环节：
- **报错型**（演练 1）——看异常栈第一行即可定位属性名；
- **静默型**（演练 2、3）——SQL 日志显示执行成功，必须靠断言或回读核对发现；
- 这也是"测试必须断言、不能只打印"的原因。
