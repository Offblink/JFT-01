二、核心知识点

2.1 ofType 与 javaType 的区别

<association> 的属性是单个对象，用 javaType 指定类型；<collection> 的属性是集合，集合本身的类型由字段声明决定，ofType 指定的是集合里元素的类型。写混了会报类型转换异常。

xml
<!-- Dept 里是 List<Emp> emps -->
<collection property="emps" ofType="com.entity.Emp">   <!-- 元素类型，不是 List -->
    <id property="empno" column="empno"/>
    <result property="ename" column="ename"/>
    <result property="job" column="job"/>
    <result property="deptno" column="emp_deptno"/>
</collection>

2.2 嵌套结果：一条 JOIN 拿到部门与全部员工

员工侧的外键列起别名 emp_deptno，部门主键用 <id>。这样 JOIN 出的多行会被 MyBatis 归并成一个 Dept 对象 + N 个 Emp 对象。

xml
<resultMap id="deptWithEmpsMap" type="com.entity.Dept">
    <id property="deptno" column="deptno"/>
    <result property="dname" column="dname"/>
    <result property="loc" column="loc"/>
    <collection property="emps" ofType="com.entity.Emp">
        <id property="empno" column="empno"/>
        <result property="ename" column="ename"/>
        <result property="job" column="job"/>
        <result property="mgr" column="mgr"/>
        <result property="hiredate" column="hiredate"/>
        <result property="sal" column="sal"/>
        <result property="comm" column="comm"/>
        <result property="deptno" column="emp_deptno"/>
    </collection>
</resultMap>

<select id="one2manyByXml" parameterType="int" resultMap="deptWithEmpsMap">
    SELECT d.deptno, d.dname, d.loc,
           e.empno, e.ename, e.job, e.mgr, e.hiredate, e.sal, e.comm,
           e.deptno AS emp_deptno
    FROM dept d
    LEFT JOIN emp e ON d.deptno = e.deptno
    WHERE d.deptno = #{deptno}
    ORDER BY e.empno
</select>

2.3 嵌套 select：部门查一次，员工查一次

主查询查部门，<collection> 上用 select 指向另一个查询、column 把 deptno 传过去。这也是 @Many 的实现原理。

xml
<resultMap id="deptWithEmpsSelectMap" type="com.entity.Dept">
    <id property="deptno" column="deptno"/>
    <result property="dname" column="dname"/>
    <result property="loc" column="loc"/>
    <collection property="emps" ofType="com.entity.Emp"
                select="com.chapter05.Chapter05EmpMapper.selectListByDeptno"
                column="deptno"/>
</resultMap>

2.4 注解版 @Many

注解版写法更紧凑，同样要求 select 写全限定名。column 的值可以带参数名，如 column="{deptno=deptno}"。

java
@Select("SELECT * FROM dept WHERE deptno = #{deptno}")
@Results({
        @Result(property = "deptno", column = "deptno"),
        @Result(property = "dname",  column = "dname"),
        @Result(property = "loc",    column = "loc"),
        @Result(property = "emps",   column = "deptno",
                many = @Many(select = "com.chapter05.Chapter05EmpMapper.selectListByDeptno"))
})
Dept one2manyByAnn(Integer deptno);

三、对照表 / 参数说明

一对多映射要点

要点说明
集合属性声明private List<Emp> emps;
XML 标签<collection property="emps" ofType="com.entity.Emp">
注解@Result(property="emps", many = @Many(select=...))
主键必须 <id>否则 JOIN 多行会被当作多个部门对象
子元素主键也建议 <id>保证员工对象不重复

六、注意事项与常见坑

📌 ofType 与 javaType 一句话区分
  • javaType：这个属性本身是什么类型（单个对象）。
  • ofType：这个集合里装的是什么类型。
⚠️ 忘了 <id> 会出现「部门重复」
  • JOIN 出 5 行员工，如果 dept 的主键写成 <result>，MyBatis 会当成 5 个部门对象。
  • 这是多表映射最高频的翻车点，务必先检查主键标签。
✅ 一对多的 N+1 更明显
  • 查 4 个部门 + 每个部门一批员工，嵌套 select 会发 1 + 4 条 SQL。
  • 列表场景优先用嵌套结果。
