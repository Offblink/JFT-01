二、核心知识点

3.1 多对多的物理结构：中间表

一个员工可以掌握多项技能，一项技能也可以被多个员工掌握，这种关系无法用外键直接表达，必须引入中间表 emp_skill(empno, skill_id)。查询时需两次 JOIN：emp → emp_skill → skill。

sql
-- 技能表
CREATE TABLE skill (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    description VARCHAR(255)
);

-- 中间表：联合主键，两个外键分别指向 emp 与 skill
CREATE TABLE emp_skill (
    empno    INT NOT NULL,
    skill_id INT NOT NULL,
    PRIMARY KEY (empno, skill_id),
    FOREIGN KEY (empno)    REFERENCES emp(empno),
    FOREIGN KEY (skill_id) REFERENCES skill(id)
);

3.2 嵌套结果版：两次 JOIN + DISTINCT

JOIN 会把「一个员工 × N 项技能」展开成 N 行，因此要 DISTINCT 去重，并用给列起别名（skill_id / skill_name / skill_desc）避免与 emp 的列冲突。映射侧用 <id property="empno"> 让 MyBatis 把多行归并成一个 Emp。

xml
<resultMap id="empWithSkillsMap" type="com.entity.Emp">
    <id property="empno" column="empno"/>
    <result property="ename" column="ename"/>
    <result property="job" column="job"/>
    <result property="sal" column="sal"/>
    <result property="deptno" column="deptno"/>
    <collection property="skills" ofType="com.entity.Skill">
        <id property="id" column="skill_id"/>
        <result property="name" column="skill_name"/>
        <result property="description" column="skill_desc"/>
    </collection>
</resultMap>

<select id="many2manyByXml" parameterType="int" resultMap="empWithSkillsMap">
    SELECT DISTINCT e.empno, e.ename, e.job, e.sal, e.deptno,
           s.id AS skill_id, s.name AS skill_name, s.description AS skill_desc
    FROM emp e
    LEFT JOIN emp_skill es ON e.empno = es.empno
    LEFT JOIN skill s ON es.skill_id = s.id
    WHERE e.empno = #{empno}
</select>

3.3 嵌套 select 版：把中间表查询抽成独立方法

注解版更直观：主查询查员工，@Many 指向「按员工编号查技能」的方法，该方法内部自己做两次 JOIN。这样 SQL 职责清晰，也便于复用。

java
@Select("SELECT * FROM emp WHERE empno = #{empno}")
@Results({
        @Result(property = "empno",  column = "empno"),
        @Result(property = "ename",  column = "ename"),
        @Result(property = "job",    column = "job"),
        @Result(property = "sal",    column = "sal"),
        @Result(property = "deptno", column = "deptno"),
        @Result(property = "skills", column = "empno",
                many = @Many(select = "com.chapter05.Chapter05EmpMapper.selectSkillsByEmpno"))
})
Emp many2manyByAnn(Integer empno);

/** 中间表查询：技能与员工的多对多关系就藏在 JOIN 条件里 */
@Select("SELECT s.id, s.name, s.description " +
        "FROM skill s " +
        "INNER JOIN emp_skill es ON s.id = es.skill_id " +
        "WHERE es.empno = #{empno}")
List<Skill> selectSkillsByEmpno(@Param("empno") Integer empno);

3.4 双向映射：Skill 侧也有 List<Emp>

多对多是双向的。Skill 里也声明了 List<Emp> emps，需要时同样可以用 collection 查出「一项技能被哪些员工掌握」。

java
public class Skill implements Serializable {
    private Integer id;
    private String name;
    private String description;

    private List<Emp> emps;   // 反向：这项技能被哪些员工掌握
}

六、注意事项与常见坑

📌 DISTINCT 与主键归并的分工
  • DISTINCT 在 SQL 层去掉重复行，减少数据传输。
  • <id property="empno"> 在映射层把多行归并成一个对象 —— 两者是互补的。
⚠️ LEFT JOIN 会产生全 null 的技能对象
  • 员工没有技能时，LEFT JOIN 会返回一行 skill 全为 null 的记录。
  • 若业务上一个技能都没有就应该是空集合，可改用 INNER JOIN 或在业务层过滤。
✅ 中间表也可以只查关系
  • 有时只需要员工编号列表而不需要技能详情，此时直接查 emp_skill 更轻量。
  • 不要为了「用上 collection」而强行多表 JOIN。
